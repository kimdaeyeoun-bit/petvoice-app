# 철인가족 간편 업데이트 배포 준비본

아직 GitHub에 게시하지 않았으며 사용자 Windows에는 설치하지 않았습니다.
예정 배포 저장소: kimdaeyeoun-bit/petvoice-app, 별도 family-ledger-updates 브랜치. 기존 main/petvoice 앱 파일은 변경하지 않습니다.
게시 대상은 Install.ps1, client.cjs, channel.json, Android-latest.apk와 releases/2026102401의 ZIP/APK 및 이 안내입니다. 운영 DB/설정/비밀번호/연결 토큰/개인 서명키는 포함하지 않습니다. 프로그램 코드에는 기존 가족 사용자 이름이 포함됩니다.

최초 1회:
- 기존 서버 창에서 Ctrl+C로 종료합니다. 상대 경로로 실행된 기존 Node 프로세스를 안전하게 식별할 수 없어 최초 한 번만 직접 종료합니다.
- 게시가 끝난 뒤 제공할 한 줄 PowerShell 명령으로 Install.ps1을 받아 실행합니다. 게시 전에는 주소가 존재하지 않습니다.
- 설치 도구는 기본 기존 폴더(USERPROFILE/FamilyLedger, LOCALAPPDATA/FamilyLedger)를 찾아 서명된 최신 파일을 받고 원본 전체 백업→검증→임시 DB 테스트→교체→실행을 요청합니다. 다중 설치/사용자 지정 경로는 자동 선택하지 않습니다.
- 바탕 화면 Update-FamilyLedger.cmd를 만듭니다. 매번 여러 텍스트 조각을 복사하지 않습니다.
- 로그인한 현재 Windows 사용자 권한으로 매일 04:00(Windows 시간대) 확인 작업을 등록합니다. 컴퓨터가 켜지고 사용자가 로그인해 있어야 합니다. 절전/로그아웃/작업 등록 권한 문제로 지연되거나 실행되지 않을 수 있습니다. 작업 등록 실패를 성공으로 보고하지 않습니다. 수동 바탕 화면 버튼은 별도로 유지됩니다.

다음 업데이트:
- 개발자가 검증한 새 버전을 이 배포 채널에 게시해야 확인할 수 있습니다. Codex가 사용자 PC를 원격 조종하는 구조가 아닙니다.
- 같거나 오래된 버전은 재설치하지 않으며, 서명/파일 해시 실패 시 실행하지 않습니다.
- 새 버전일 때 포트 3210에서 해당 설치 경로의 node server.cjs로 식별된 프로세스만 중지합니다. 다른 Node 프로세스나 출처 불명 프로세스는 종료하지 않습니다.
- 전체 백업과 이전 폴더를 보존합니다. 사용자 데이터/설정/키는 새 배포 파일에 넣지 않습니다.
- 설치 테스트는 모두 별도 임시 SQLite를 사용합니다. 운영 DB는 읽기 전용 무결성 검사와 중지 후 파일 백업만 합니다.
- 서버 실행 확인에 실패하면 백업과 오류를 남깁니다. 사용자 거래를 잃을 수 있는 자동 DB 되돌리기는 하지 않습니다.
- 웹 화면은 같은 기존 주소에서 새로고침합니다. 가계부 설정의 APK 버튼으로 휴대폰이 직접 새 앱을 받을 수 있게 준비했습니다. Android 앱 설치/문자 권한은 각자가 직접 허용해야 합니다. Play Protect 차단을 우회하지 않습니다.

검증 결과:
- 실제 PowerShell 7(Linux)에서 설치/구동 스크립트 구문 검사 통과.
- 실제 PowerShell 7에서 임시 가짜 설치 폴더로 업데이트 적용 통과: 손상된 파일 거부, 전체 백업, 복사한 가짜 DB/개인 설정/임의 비공개 파일 해시 유지, 이전 폴더 보존.
- RSA 서명·잘못된 키·변조·예상 외 다운로드 주소·손상된 ZIP·다운그레이드 거부와 같은 버전 무변경 테스트 통과.
- 압축 해제된 배포본의 임시 SQLite 금융 기능/마이그레이션/결산/문자 파서 테스트 통과.
- ZIP 데이터·환경 설정·개인키·운영 DB 미포함, 내부 파일 SHA256 확인 통과.
- 미검증: 실제 Windows PowerShell 5.1, Windows 작업 스케줄러, 프로세스 식별/중지 및 cmd 서버 재실행, 사용자의 실제 설치 경로·네트워크. 실제 Galaxy 문자 권한/수집/절전도 앞선 검증 범위와 동일하게 미검증.

개발 메모:
- 각 공개 버전 경로는 한번 게시하면 변경하지 말고 더 큰 version으로 새 경로를 만듭니다. 기존 배포 브랜치를 덮어쓰거나 main을 교체하지 않습니다.
- release-private.pem은 workspace/backups/updater-signing에만 있습니다. 배포 ZIP/소스/공개 Git에 절대로 넣지 않습니다. 개인키를 잃으면 고정된 클라이언트가 새 서명을 신뢰하지 않으므로 별도 안전한 비공개 백업이 필요합니다.
